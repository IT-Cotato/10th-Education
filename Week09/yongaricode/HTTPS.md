# HTTPS

# **1. HTTP 개념 정리**

## 1-1. HTTP란?

- HTTP는 웹 브라우저와 웹 서버 간에 HTML, CSS, 이미지, 동영상 등 다양한 리소스를 주고받을 때 사용됨.
- 기본적으로 클라이언트가 요청을 보내면, 서버가 응답을 보내는 방식으로 동작함.
- REST API는 HTTP를 기반으로 데이터를 주고받는 규칙
- HTTP가 데이터를 주고받는 방식(요청-응답 모델)

## 1-2. HTTP의 주요 특징(무상태성, 비연결성)

### 1) 무상태성(Stateless)

- 서버가 클라이언트의 정보를 기억하지 않음.
- 클라이언트는 요청을 보낼 때마다 필요한 정보를 전부 포함해서 보내야 함.
- 장점: 서버가 많아도 문제없이 확장 가능

### 2) 비연결성(Connectionless)

- 요청을 주고받을 때만 연결하고, 응답을 보내면 바로 연결을 끊는 방식
- 장점: 서버의 자원을 아낄 수 있어서 빠른 응답이 가능
- 단점: 요청이 많아질수록 매번 연결을 새로 맺고 끊어야 하므로 비효율적일 수 있음
    - 이를 보완하기 위해 HTTP 지속 연결이 도입

## **1-3. HTTP 단점**

- HTTP는 암호화되지 않은 평문 전송을 사용함.
- 해커가 데이터를 가로챌 가능성이 있음.
- 보안이 취약하여 중간자 공격에 노출될 위험이 큼.

# 2. HTTPS

## 2-1. HTTPS란?

- HTTPS는 HTTP + 보안(SSL/TLS)임.
    - 초기에는 SSL을 사용했지만, 현재는 **더 안전한 TLS**가 표준임.
    - 여전히 "SSL/TLS" 혹은 "SSL 인증서"라는 용어가 사용됨.
- 웹사이트에서 HTTPS를 적용하면 보안이 강화됨.

## 2-2. HTTPS의 필요성

### 1) 데이터 암호화

- HTTPS는 데이터를 암호화하여 안전하게 전송함.
- 중간자 공격(Man-in-the-middle attack)으로부터 정보를 보호할 수 있음.

### 2) 사이트 신뢰성 보장

- 사용자가 접속한 사이트가 신뢰할 수 있는 사이트인지 보장함.
- 피싱 사이트와 공식 사이트를 구별할 수 있음.

### 3) 데이터 무결성 보장

- 데이터가 변조되거나 조작되지 않았음을 확인할 수 있음.
- 예를 들어, 은행 계좌 잔액 정보가 해커에 의해 변조되지 않도록 보호할 수 있음.

# 3. SSL/TLS 암호화

## 3-1. SSL/TLS 암호화 방식

### 1) 대칭키 암호화

- 서버와 클라이언트가 **동일한 키**를 공유하여 데이터를 암호화 및 복호화하는 방식임.
- 장점: 속도가 빠르고 효율적임.
- 단점: 키를 안전하게 공유하는 것이 중요함. (해커가 키를 가로채면 보안 위협 발생)

### 2) 비대칭키 암호화

- 서로 다른 두 개의 키(공개키, 개인키)를 사용하는 방식임.
- 공개키로 암호화된 데이터는 개인키로만 복호화할 수 있음.
- **데이터 보호와 인증을 동시에 보장할 수 있는 강력한 보안 시스템**임.

## 3-2. SSL/TLS 인증서 발급 과정

1. 서버는 **비대칭키(공개키, 개인키)를 생성**함.
2. 서버는 자신의 공개키와 웹사이트 정보를 CA(Certificate Authority)에 제출함.
3. CA는 서버의 정보를 검증한 후, 서버의 공개키가 포함된 **SSL/TLS 인증서를 발급**함.
4. CA는 자신의 개인키로 인증서를 암호화한 뒤 서버에 전송함.
5. 서버는 인증서를 받아 HTTPS 설정을 완료함.
6. 사용자는 브라우저를 통해 웹사이트에 접속할 때 인증서를 확인하고, 안전한 연결을 확립함.

## 3-3. SSL/TLS 핸드셰이크 과정

1. 클라이언트(브라우저)가 서버에 HTTPS 연결 요청을 보냄.
2. 서버는 CA에서 받은 SSL/TLS 인증서와 공개키를 클라이언트에게 전송함.
3. 클라이언트는 CA의 공개키로 인증서를 검증함.
4. 클라이언트는 Pre-Master Key를 생성하고, 서버의 공개키로 암호화하여 전송함.
5. 서버는 자신의 개인키로 Pre-Master Key를 복호화함.
6. 서버와 클라이언트는 Pre-Master Key를 이용해 세션 키(대칭키)를 생성함.
7. 이후의 데이터 전송은 대칭키 암호화를 통해 빠르게 이루어짐.

# 4. HTTPS의 중요성

- HTTPS를 사용하면 데이터를 **암호화하여 전송**할 수 있음.
- 보낸 사람이 **신뢰할 수 있는지 검증**할 수 있음.
- 데이터가 **변조되지 않았음을 보장**할 수 있음.
- 검색 엔진 최적화(SEO)에도 긍정적인 영향을 줌.
    - 구글은 HTTPS를 사용하는 웹사이트의 검색 순위를 더 높게 평가함.
