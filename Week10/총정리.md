# CS 교육 총정리

## 1. 동기 / 비동기와 블록 / 논블록

### 🔹 동기 (Synchronous)

- 요청한 작업이 완료될 때까지 **순차적으로 처리.**
- 작업 흐름이 **차단되는 방식.**

### 🔹 비동기 (Asynchronous)

- 요청한 작업의 **완료 여부와 관계없이** 다음 작업 수행.
- 작업 흐름이 **차단되지 않는 방식.**

### 🔹 블록 (Blocking)

- **전체 작업 흐름을 차단.**
- 예시: 파일을 블로킹 방식으로 읽으면 **다 읽을 때까지 대기.**

### 🔹 논블록 (Non-blocking)

- **작업 중에도 다른 작업 수행 가능.**
- 예시: `setTimeout`을 사용한 비동기 논블로킹 코드.

## 2. TCP와 UDP

### 🔹 TCP (Transmission Control Protocol)

- **연결형 서비스:** 전송 순서와 수신 확인을 보장.
- **핸드셰이크 (Handshake)** 과정으로 **신뢰성 보장.**
- **사용 예시:** 파일 전송, 웹 브라우징.

### 🔹 UDP (User Datagram Protocol)

- **비연결형 서비스:** 전송 순서와 수신 확인을 보장하지 않음.
- **빠른 속도:** 핸드셰이크가 없으므로 **실시간 스트리밍**에 유리.
- **사용 예시:** 온라인 게임, 실시간 스트리밍.

## 3. WebSocket

### 🔹 HTTP 통신

- **요청-응답 방식:** 클라이언트가 요청해야만 서버가 응답.
- **단점:** **실시간 양방향 통신에 비효율적.**

### 🔹 WebSocket

- **양방향 실시간 통신:** 핸드셰이크 후 자유롭게 데이터 전송.
- **장점:** **추가 요청 없이** 실시간 데이터 송수신 가능.

### 실시간 통신 방식

### 🔹 1. Polling

- 클라이언트가 **일정 주기로 서버에 요청.**
- **네트워크 부하가 큼.**

### 🔹 2. Long Polling

- **이벤트 발생 시까지 대기 후 응답.**
- **효율성 향상:** 자주 요청하지 않음.

### 🔹 3. Streaming

- **한 번 요청 후 지속적으로 응답.**
- **단방향 실시간 통신:** 서버 → 클라이언트.

## 4. 웹 렌더링

### 🔹 MPA (Multi-Page Application)

- **서버에서 전체 페이지를 요청.**
- **새로고침:** 페이지 전환 시마다 **서버 요청 발생.**

### 🔹 SPA (Single Page Application)

- **한 번 로드된 HTML, CSS, JS 유지.**
- **비동기 요청:** 필요한 데이터만 요청해 **빠른 전환.**

### 🔹 CSR (Client-Side Rendering)

- **클라이언트에서 렌더링.**
- **장점:** 동적인 UI 가능.
- **단점:** **초기 로딩이 느림.**

### 🔹 SSR (Server-Side Rendering)

- **서버에서 렌더링 후 전송.**
- **장점:** SEO 최적화와 빠른 초기 로딩.
- **단점:** **페이지 전환 시 서버 요청 부담.**

### 🔹 SSG (Static Site Generation)

- **정적 페이지 사전 생성.**
- **장점:** 빠른 로딩과 낮은 서버 부하.
- **단점:** **실시간 데이터 반영 어려움.**

### 🔹 ISR (Incremental Static Regeneration)

- **SSG의 단점을 보완:** 주기적으로 페이지 갱신.
- **장점:** 빠른 로딩 + **일부 실시간 데이터 반영.**

### 🔹 유니버설 렌더링 (Universal Rendering)

- **SSR + CSR의 장점 결합.**
- **초기 로딩 속도 + 동적인 UI 모두 지원.**

## 5. CORS (Cross-Origin Resource Sharing)

### 🔹 SOP (Same-Origin Policy)

- **동일 출처**가 아니면 리소스 접근 차단.

### 🔹 CORS 해결 방법

1. **OPTIONS 요청:** 보안이 중요한 요청은 **사전 검사.**
2. **프록시 서버:** **서버 설정이 어려울 때** 대안.

---

## 6. HTTPS (HyperText Transfer Protocol Secure)

### 🔹 HTTPS란?

- **HTTP + SSL/TLS**로 **데이터 암호화**와 **보안 통신**을 제공하는 프로토콜.

### 🔹 HTTPS가 필요한 이유

1. **데이터 암호화:** 정보가 **평문이 아닌 암호화**되어 전송. 🔒
2. **인증:** **SSL 인증서**로 서버 신원 확인. 🔑
3. **데이터 무결성:** **전송 중 변조 방지.** 🛡️

### 🔹 HTTPS 통신 과정

1. **서버:** SSL 인증서 전송 🔑
2. **클라이언트:** 인증서 검증 🛡️
3. **암호화된 세션 키 교환 🔄**
4. **암호화된 데이터 통신 🔒**
